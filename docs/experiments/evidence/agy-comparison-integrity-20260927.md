# 정량 비교 목적 보존 및 계측 수정

사용자의 "목적에 반하지 않도록 계속" 요청에 따라, 현재 선언된 자료·권한 경계를
유지하고 관측되지 않은 값을 성공이나 0으로 치환하지 않는다.

## 수정 및 검증

AGY의 shell tool은 CMake 실패를 출력하고도 `DONE`을 반환했다. 종료 코드가 없는
`DONE`을 성공으로 센 기존 failed_commands는 실제 실패 수를 과소 집계했다.

- 명시적 tool error/nonzero exit가 확인되면 실패 하한에 포함한다.
- 명령 하나라도 exit가 미확인이면 총 `failed_commands`는 `null`이다.
- 명령 출력의 "OK"/"exit 0" 문자열로 성공을 추정하지 않는다.
- 파일 읽기 거부는 shell 실패 수와 구분한다.
- 다음 실행의 `command-audit.json`에 원본 stdout hash, step별 관측 상태,
  미확인 수·실패 하한·집계 한계를 기록하고 manifest evidence hash에 포함한다.
- 회귀 시험 5개를 추가했고 전체 107개 시험이 통과했다.

기존 원본 manifest와 archive는 수정하지 않았다. [별도 재분석](agy-command-audit-20260927.json)은
원본 hash와 연결되며 기존 run의 새 실험 결과가 아니다.

| 9월 27일 run | shell 호출 | 확인된 실패 하한 | exit 미확인 | 총 실패 명령 수 |
|---|---:|---:|---:|---|
| r01 | 29 | 1 | 28 | null |
| r02 | 21 | 1 | 20 | null |
| r03 | 7 | 0 | 7 | null |

r02의 수동 출력 검토에서는 최소 5건의 실패가 보인다. 이는 tool error 하한 1과
다른 근거이며, CLI가 보고하지 않은 모든 종료 코드를 복원했다는 뜻은 아니다.

## 조건과 판정

1. 현재 권한 목록과 제품 기준은 그대로 둔다. r03의 vendor/build 조회 거부는
   선언된 자료 경계를 위반한 요청으로 보존하며, 그 경로를 새로 허용하지 않는다.
2. 과거 pilot의 입력·권한 보완은 준비 이력이다. 입력 hash가 다른 run을 반복 표본으로
   합치거나 가장 좋은 결과만 골라 agent 성능으로 발표하지 않는다.
3. r02 host C/CTest·Python 시험 재현은 부분 제품 증거다. 완성 firmware·실물 동작·
   구조화 E2E 결과를 대체하지 않는다. 성공 기준을 낮추지 않는다.
4. 정식 비교 전 baseline/profile/입력 bundle·반복 계획을 고정하고 실패·중단도 함께
   보존한다. 미관측 metric은 제외 사유와 함께 별도 표시한다.
5. 환경 준비, 실행 계측 검증, 제품 합격, 정량 순위 적격성은 각각 판정한다.
   컴파일러가 준비됐다는 사실만으로 제품 또는 AGY 완주를 통과 처리하지 않는다.

현재 상태는 환경 preflight 통과, 계측의 과소 집계 수정, 제품 pilot 미통과다.
AGY가 제공하지 않는 exit code의 완전한 확보는 남은 관측 한계이며, 실패 명령 수
순위는 산출하지 않는다. 공식 benchmark 및 제품 flash는 아직 수행하지 않았다.
