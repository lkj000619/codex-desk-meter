# Codex 기준 제품과 에이전트 비교 — 2026-09-29 방향 전환

## 목적

사용자 지시: Codex로 Desk Meter 기준 제품을 먼저 만든다. 각 에이전트에 같은
시작 프롬프트와 문서를 주어 첫 결과를 비교한다. 이후 기준 제품 수준에
도달하기까지의 수정 횟수, 토큰, 시간과 개입을 비교한다.

부족한 기능과 실행 실패도 비교 결과다. 모든 후보의 전체 합격을 실험 시작의
선행 조건으로 요구하지 않는다. 첫 결과 평가 뒤 발견한 부족한 기능 때문에
공통 입력을 계속 바꾸지 않는다.

## 순서와 종료 조건

1. **Codex 기준 제품 제작:** 별도 작업공간에서 펌웨어와 PC 프로그램을 작성하고
   빌드·시험한다. 보드에서 표시·조작·데이터 전달을 확인해 기준 구현 commit을 고정한다.
   기준 제작은 보완 가능한 개발 과정이며 단회 비교 순위의 대상이 아니다.
2. **비교 조건 한 번 고정:** 기준 제품에서 실제 확인한 기능을 같은 입력·조작으로
   확인할 목록으로 만든다. 기준 제품에도 확인되지 않은 조건은 판정할 수 없음으로
   기록한다. 후보 코드의 동일성이나 픽셀 단위 화면 복제를 요구하지 않는다.
3. **첫 결과 비교:** 각 후보는 동일한 제품 코드 없는 시작 자료와 공통 프롬프트를
   받는다. 종료 시 코드를 보존하고 구현된 기능·누락·오류·빌드 결과를 평가한다.
   실패 후보도 표에 남긴다. Codex 기준 소스와 다른 후보의 소스는 제공하지 않는다.
4. **수정 비용 비교:** 같은 평가 목록에 따른 관측 사실과 기대 동작으로 후속
   지시를 만든다. 후보 자신의 결과에서 이어서 수정하고 매 회차를 기록한다.
   처음부터 재시작한 시도는 별도로 표시한다. 구현 방법이나 다른 후보 코드의
   제공은 개입으로 기록한다. 기준 도달 시 종료하며, 공통 한도에 닿으면 미도달로 종료한다.

기존 단회 규칙은 기존 실행에 그대로 보존한다. 새 비교에서는 첫 결과와 후속
수정 과정을 둘 다 평가한다. 후속 지시와 한도는 후보 실행 전에 공통으로 고정한다.
실제 Codex 계정 연동은 문서의 fixture 비교 범위와 구분해 기록한다.

## 최소 기록

| 단계 | 기록 |
|---|---|
| 첫 실행 | agent/표면/model/설정, 시작 자료·프롬프트 hash, 코드 commit, 기능별 결과, 시간, 토큰 |
| 수정 회차 | 정확한 후속 지시, 이전/이후 commit, 해결·잔여 항목, 시간, 토큰, 운영자 개입 |
| 누적 | 첫 실행+수정의 시간·토큰, 수정 회차 수, 기준 도달 또는 한도 종료 |

input/output/cached/reasoning/provider total은 원본 정의를 보존한다. 미제공 값은
null로 남긴다. 계측 정의가 다른 제공자의 토큰 총량을 같은 단위의 효율 순위로
단정하지 않는다. 준비·환경 수리·실물 평가 시간은 에이전트 작성 시간과 별도 기록한다.

## 시작 자료와 기존 AGY 이력

우선 시작 자료는 AGY 첫 제품 실행의 고정본
`aab0d493888f4fc0bb6eff726bfe7d93b167543c`로 잡는다. 이는 2026-09-29 운영자의
해석이며 프로젝트 최초의 문서 버전이라는 주장은 아니다. 실제 후보 비교 입력은
기준 제품 제작 후 원문·공통 운영 안내와 hash를 확정한다.

기존 AGY 첫 결과와 r01~r21 보완은 삭제하지 않는다. 프롬프트·정책·범위 변경이
있었던 역사적 개발 비용으로 보존하며, 새 고정 조건 비교와 직접 같은 조건의
순위로 합치지 않는다. 기존 `product_pass:false`와 원본 평가를 변경하지 않는다.

현재 단계: **Codex 기준 제품 제작 시작 준비. 후보 비교는 아직 시작하지 않음.**
