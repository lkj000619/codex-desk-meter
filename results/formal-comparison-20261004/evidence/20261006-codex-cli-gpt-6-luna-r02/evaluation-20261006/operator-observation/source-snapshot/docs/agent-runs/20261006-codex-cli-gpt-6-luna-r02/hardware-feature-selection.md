# 온보드 기능 후보와 선택

## 후보

| ID | 기능 | 사용자 가치 | 자원 | 구현 비용 | 위험 | 검증 방법 |
|---|---|---|---|---|---|---|
| H1 | 상호작용이 없으면 백라이트를 낮추고 BOOT 입력 뒤 복구 | 장시간 켜 둔 계기의 눈부심과 전력 소비를 줄이고 화면을 다시 볼 때 즉시 밝게 한다 | 제조사 자료의 active-low GPIO6 백라이트만 사용한다. 추가 주변장치나 계정이 필요 없다 | 단조 시간 기반 정책 모듈, 앱의 밝기 갱신, 정책 경계 host 시험 | active-low PWM 극성을 반대로 적용하거나 입력 시 밝기 복구를 놓치면 화면이 어둡게 남을 수 있다 | `idle_dim` CTest에서 idle 경계와 상호작용 시 복구를 확인하고, 보드에서는 밝기 변화와 복구를 눈으로 확인한다 |

## 선택

H1 백라이트 idle dim을 선택했다. 핵심 수신·표시 경로와 분리된 `components/idle_dim_policy` 모듈에 정책을 두고 앱은 그 결과만 백라이트 드라이버에 전달한다. 보드에 이미 있는 GPIO6만 사용하고 host C 테스트가 정책을 실행한다. 화면이 어두워지는 시간이 길어져도 BOOT 상호작용은 즉시 정상 밝기를 복구하도록 구현했다.

H2는 IMU 드라이버와 자세 debounce가 새 상호작용 상태를 추가하고, 방향 오판 시 LCD의 기본 가로 UI를 방해할 위험이 있어 제외했다. H3는 배터리의 실제 장착 여부와 ADC 보정값을 확인하지 않고 수치를 표시할 수 없어서 제외했다. 두 기능은 추가 부품이나 인터넷 연결을 요구하진 않지만, 이 실행에서 필요한 보드 관측과 검증 비용이 H1보다 크다.

H1의 host 정책 시험은 `ctest --test-dir build-host --output-on-failure`에 포함된다. 실물 밝기와 복구는 후보 실행 중 측정하지 않았으며 운영자 확인이 남아 있다. 제조사 화면 데모 반복은 후보로 세지 않았다.

결과 JSON의 F9 점수는 후보의 자체 점검 기록이며 운영자 평가 점수가 아니다. 보드 관측이 끝나기 전에는 F9를 `partial`로 유지한다.
