# AGY 이력과 Codex 기준 제작 비교 — 2026-10-01

## 결론

두 진행은 테스트 데이터 기반 PC→USB→ESP32→LCD 제품을 만들고 보완한 개발 이력이다. 현재 같은 프롬프트·문서·실행 조건에서 얻은 두 후보의 정식 비교 결과는 아니다. 실제 계정 사용량 자동 수집은 양쪽 모두 구현되지 않았다.

## 수행 방식과 산출물

| 항목 | 기존 AGY | 이번 Codex 기준 제품 |
|---|---|---|
| 역할 | 제한된 pilot 실행 및 이후 별도 보완 | 다른 후보의 목표 동작을 정하기 위한 기준 제품 제작 |
| 실행 표면/모델 | Antigravity CLI AGY 1.2.11 / gemini-3.8-flash-medium | 원래 Codex Desk Meter 제작 세션 / 기록상 gpt-6-luna |
| 시작 문서 | 9월 28일 첫 제품 실행 baseline aab0d49 | 동일 baseline aab0d49의 문서에서 별도 작업공간 시작 |
| 실제 지시 | 공통 과제 프롬프트, 명령별 제한, run-context·결과 제출 규칙; 이후 회차별 보완 지시 | 기준 제작 운영 안내를 추가하고 단회·승인·AGY 권한 gate를 적용하지 않음; 후속 수정 허용 |

| PC 프로그램 | fixture 수집·정규화·직렬 송신, 주기 송신과 순번 유지 | Python CLI fixture 수집·정규화·직렬 송신, 5~60초 주기 및 순번·로그 저장 |

| 선택 하드웨어 기능 | IMU 회전 구현 및 영상 관측 | RTC 시간 유지 구현·자동 시험; 전원 차단 후 유지 실물 확인은 없음 |
| 실물 근거 | 표시·BOOT·IMU·RST 복구·USB 재전원 복구 영상, 짧은 입력 일부 시간 추정 | 업로드·프레임 수락 로그, 값 표시·세 화면 전환 영상 |
| 실제 계정 사용량 | 미구현 | 미구현 |
| 비교에서 사용할 성격 | 기존 조건 변경·환경 실패를 포함한 역사적 개발 이력 | 보완 가능한 기준 제작 이력; 단일 후보의 독립 첫 실행 점수가 아님 |

같은 시작 문서 commit이라는 사실이 실제 프롬프트와 권한, 수정 기회까지 같았다는 뜻은 아니다. 이번 기준 제품 제작 안내 자체가 운영 조건을 변경한다.

## 이번 제작 및 운영 세션에서 실제 수행한 일

1. 원래 제작 세션이 펌웨어, PC fixture 송신기, 자동 시험과 빌드 산출물을 작성했다. 첫 구현은 `6ccdeb1`이다.
2. 운영자가 USB 수신·BOOT 렌더링 및 시험 수정 `04dd1a0`을 작성했다. 사용자가 원래 제작 세션에서 계속하라고 정정했으며, 이후 해당 수정은 최종 제품에 남았다. 최종 제품을 원래 제작 세션만의 독립 작성 결과라고 부를 수 없다.
3. 운영자가 초기 결과를 검증하고 보드 기존 앱을 백업한 뒤 업로드했다. 정상 fixture 수신 중 메모리 오류와 재부팅을 발견했다.
4. 원래 제작 세션이 수신 stack 문제(`1e17bc4`), Windows 송신 명령 조회 문제(`eb1264f`), 백라이트 극성 문제(`7923f96`)를 각각 수정했다.
5. 운영자가 최종 자동 시험 Python 15개·CTest 4개 결과, 앱 업로드/독립 flash 검증, 실제 프레임 순번 0·1 수락을 확인했다. 사용자 확인과 10월 1일 영상에서 값 표시 및 세 화면 전환을 기록했다.

이번 업로드 과정에서 운영자가 제품 소스를 추가 수정하지 않았다는 기록은 2번의 이전 구현 개입을 없애지 않는다. 최신 영상의 검토는 기본 표시와 전환의 확인이며 전체 제품 합격 판정은 아니다.

## 이전 AGY 진행의 해석

9월 28일 첫 제품 실행은 구현 `9d52fa5`를 남겼으나 미등록 시험 명령과 결과 미제출로 `environment_failed`로 기록됐다. 독립 빌드는 성공했다. 이후 r01~r21 보완 식별자가 있으며, 이 번호가 21회의 성공한 기능 수정이라는 뜻은 아니다. 환경 실패·부분 수정·진단·시작하지 않은 준비 회차도 포함한다.

최종 r21 구현은 `8eb40c0`이다. 영상에는 값, 공급자/화면 전환, IMU 회전, RST 및 USB 재전원 후 값 복구가 기록됐다. 기존 `product_pass:false`, `ranking_eligible:false`는 그 당시 계약 전체를 충족했다는 증거가 없다는 판정이며, 제품 산출물이 없거나 모든 기능이 실패했다는 뜻이 아니다. 이를 이유로 새 후보 실행을 막지 않는다.

## 시간과 토큰을 읽는 방법

- AGY 첫 제품 실행: 877.610초, provider total 1,783,064. 이는 해당 실행의 값이다.
- AGY 보완 r21: 871.828초, provider total 1,617,249. 이것을 AGY 전체 개발 비용으로 사용할 수 없다.
- Codex 원래 제작 세션의 마지막 보존 누적값: total 29,704,743, cached input 28,751,360. 이는 세션 전체 값이고 운영자 세션 비용은 제외돼 있다. cached/reasoning을 total에 다시 더하지 않는다.
- 회차별 AGY 비용, Codex 세션 누적 비용은 집계 범위와 제공자 정의가 다르다. 이 숫자만으로 어느 에이전트가 더 저렴하거나 빠르다고 평가하지 않는다.

## 프로젝트 목적에 따른 현재 위치

사용자가 원하는 것은 같은 최초 입력에서 나온 첫 결과와 같은 목표 수준까지의 수정 횟수·시간·토큰 비교다. 지금은 두 구현과 보완·실물 관측을 확보했으며, 새 공통 조건 후보 비교는 아직 시작되지 않았다.

실제 계정 사용량 자동 수집을 완성 제품의 목표에 포함할지, 현재 fixture 기반 동작을 먼저 비교할지는 공통 목표에 명시해야 한다. 최초 평가 뒤 발견한 누락은 후보의 평가 결과로 남기며 문서와 기준을 계속 늘리는 이유로 삼지 않는다. 후보 시작에 전체 합격을 선행 조건으로 요구하지 않는다.
